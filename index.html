Beginner · 1

What is a robot?

A robot is a machine that receives information, makes a decision, and produces an action. In this simulator, the robot sees the environment through sensors and reacts by moving its wheels.

  • Sense: read sensor values
  • Think: decide what to do
  • Act: move the motors
Detailed explanation and example

How it works

A robot is a system that interacts with its surroundings. A sensor provides input, a controller runs instructions, and an actuator (such as a motor) produces output. The simulator models these parts in software.

Example: approaching a wall

The distance sensor reports a measurement. The program compares that number to a safe limit. The motors then keep moving or turn. The robot only follows the rules we provide; it does not understand the wall like a person.

Try it: In Simulator, select Obstacle arena and run the example. Watch the sensor reading and robot movement change together.

Beginner · 2

The basic robot loop

Robots usually repeat the same cycle many times per second. This is called a control loop. Each cycle: measure, decide, move.

const distance = robot.distance();
if (state.escapeTicks > 0) {
  state.escapeTicks--;
  if (state.escapeTicks > 24) {
    robot.drive(-0.55, -0.55);
  } else {
    robot.drive(-0.55, 0.55);
  }
} else if (distance < 22) {
  state.escapeTicks = 42;
  robot.drive(-0.55, -0.55);
} else {
  robot.drive(0.7, 0.7);
}

Every tick is a new decision. When an obstacle is close, the robot needs several ticks to back away and turn before it can continue.

Detailed explanation and example

One cycle at a time

Each cycle reads current sensor values, evaluates the condition, and sets motor power. The next cycle repeats with new values. This is feedback: an action changes the situation that will be measured next.

Walk through the decision

If the measured distance is 12, then 12 < 15 is true, so the first drive command runs. If the distance is 25, the condition is false and the else command runs.

Try it: Change the threshold from 15 to 30, run the code, and observe when the robot starts turning.

Beginner · 3

Sensors: the robot's eyes

Sensors are inputs. They tell the robot what is happening around it. In this simulator, the robot can detect distance and black lines.

  • robot.distance() returns the distance to the nearest obstacle.
  • robot.lineLeft() checks the left sensor.
  • robot.lineRight() checks the right sensor.

Think of sensors as the robot's eyes and touch.

Detailed explanation and example

Sensor values are measurements

robot.distance() returns a number in centimeters for the nearest obstacle in front, up to the simulator's sensing range. The line sensors return Boolean values: true means that sensor is over the dark track; false means it is not. The line sensors are useful in Line track mode.

Example: store a reading

const ahead = robot.distance();
if (ahead < 25) {
  robot.drive(0, 0);
}

Try it: Select Line track and read the L/R status above the canvas. Move the robot and compare those readings with the colored sensor dots.

Beginner · 4

Motors: the robot's muscles

Motors move the robot. We control them with left and right wheel power. The values are between -1 and 1.

robot.drive(0.8, 0.8);   // forward
robot.drive(-0.8, -0.8); // backward
robot.drive(0.8, 0.1);   // turn right
robot.drive(0.1, 0.8);   // turn left

Positive values move forward. Negative values reverse direction. The difference between the two values creates rotation.

Detailed explanation and example

Why two wheel values?

This simulator uses a two-wheel drive model. Equal wheel speeds move mostly straight. Different speeds curve the robot. Opposite speeds make it rotate around its center. A value near zero slows one wheel while the other keeps moving.

Example: gentle curve

robot.drive(0.8, 0.4);

The left wheel is faster than the right, so the robot curves right. Exact turning behavior also depends on speed and how long the command is applied.

Try it: Compare drive(0.6, 0.6), drive(0.8, 0.3), and drive(-0.5, 0.5).

Beginner · 5

Moving forward

The simplest robot program is to keep both wheels moving forward.

robot.drive(0.7, 0.7);

This is the base of many autonomous robot behaviors. A robot without motion is just an object.

Detailed explanation and example

Command values

The first number controls the left wheel and the second controls the right. Both are positive and equal, so both wheels push forward at the same power. Values closer to 1 are faster; values closer to 0 are slower.

Example: stop and go

robot.drive(0, 0);     // stop both wheels
robot.drive(0.3, 0.3); // slow forward
robot.drive(1, 1);     // faster forward

Since the program runs repeatedly, a drive command is continuously refreshed while it remains in the program.

Try it: Run the simple forward command, then change both values to 0.3 and compare the motion.

Beginner · 6

Obstacle avoidance

An obstacle-avoidance robot checks whether there is something too close ahead. If yes, turn; otherwise, keep going.

if (state.escapeTicks > 0) {
  state.escapeTicks--;
  if (state.escapeTicks > 24) {
    robot.drive(-0.55, -0.55); // reverse
  } else {
    robot.drive(-0.55, 0.55);  // then turn
  }
} else if (robot.distance() < 22) {
  state.escapeTicks = 42;
  robot.drive(-0.55, -0.55);
} else {
  robot.drive(0.7, 0.7);
}

This teaches a key robotics idea: decisions depend on sensor input. The robot reverses first so it has room to turn instead of spinning against an obstacle.

Detailed explanation and example

Why reversing matters

If a robot is already close to a wall, spinning in place can leave its body pressed against the wall. First reverse to create clearance; then turn; only then drive forward again. The red sensor ray reports what is ahead, while collision physics correctly prevents the robot body from passing through an obstacle.

Recovery sequence

if (state.escapeTicks > 0) {
  state.escapeTicks--;
  if (state.escapeTicks > 24) {
    robot.drive(-0.55, -0.55); // reverse first
  } else {
    robot.drive(-0.55, 0.55);  // turn after backing up
  }
} else if (robot.distance() < 22) {
  state.escapeTicks = 42;
  robot.drive(-0.55, -0.55);
} else {
  robot.drive(0.7, 0.7);
}

The counter keeps each maneuver active over many control-loop ticks. It also avoids trying to move forward while the sensor still sees the same obstacle.

Try it: Load the lesson in the simulator. Watch the robot reverse, turn, and then find a clear direction. Adjust the distance threshold if it starts too late.

Intermediate · 7

If, else, and conditions

Conditions are the core of robot intelligence. They allow the robot to react to different situations.

if (robot.distance() < 20) {
  robot.drive(0.5, -0.5);
} else if (robot.distance() < 40) {
  robot.drive(0.6, 0.6);
} else {
  robot.drive(0.9, 0.9);
}

The robot is not just moving blindly. It is checking data and choosing a behavior.

Detailed explanation and example

Conditions are checked in order

The program checks the first condition. Only when it is false does it check the next else if. The final else is the fallback. Put the most urgent or specific cases first so a broad condition does not hide them.

Example: three distance zones

  • Under 20 cm: turn away.
  • From 20 to under 40 cm: move carefully.
  • 40 cm or more: move faster.

Notice that the middle condition does not need to say distance() >= 20: reaching it already means the first condition was false.

Try it: Add a new condition for a very close obstacle and make the robot stop before turning.

Intermediate · 8

Line following

Line following makes the robot follow a track. The robot checks both line sensors and reacts to the direction of the line.

const L = robot.lineLeft();
const R = robot.lineRight();

if (L && R) {
  robot.drive(0.7, 0.7);
} else if (L) {
  robot.drive(0.1, 0.7);
} else if (R) {
  robot.drive(0.7, 0.1);
} else {
  robot.drive(0.5, -0.5);
}

This is one of the classic beginner robotics tasks. You learn how feedback makes a robot correct its path.

Detailed explanation and example

Interpret the two sensors

There are four possible readings: neither sensor sees the line, only the left sees it, only the right sees it, or both see it. Each case needs a motor response. When the left sensor sees the line, slowing the left wheel relative to the right curves the robot toward the line.

Decision table

  • L=true, R=true: drive straight over the line.
  • L=true, R=false: curve left.
  • L=false, R=true: curve right.
  • L=false, R=false: line is lost; search for it.

Try it: Switch the simulator to Line track, use the example, and adjust the smaller wheel power to make turns gentler or sharper.

Intermediate · 9

Memory with state

Robots often need to remember things between loops. This is done with state.

if (robot.distance() < 20) {
  state.lastTurn = 'left';
  robot.drive(-0.4, 0.7);
} else if (state.lastTurn === 'left') {
  robot.drive(0.7, 0.2);
} else {
  robot.drive(0.8, 0.8);
}

state is like short-term memory. It helps the robot continue a behavior after a sensor event.

Detailed explanation and example

What state remembers

The program body is called again on every tick, so ordinary local variables are created again each time. The simulator's state object persists between ticks. Store information there when a later decision needs it.

Example: remember a search direction

if (robot.lineLeft()) state.lastSeen = 'left';
if (robot.lineRight()) state.lastSeen = 'right';

if (!robot.lineLeft() && !robot.lineRight()) {
  if (state.lastSeen === 'left') robot.drive(-0.2, 0.5);
  else robot.drive(0.5, -0.2);
}

This remembers which side last detected the line so the robot can search that way after losing it.

Try it: Change the saved directions and observe how the robot searches when both sensors are off the line.

Advanced · 10

Behavior-based robotics

Advanced robots combine many simple rules into one system. For example, they might avoid obstacles, follow a line, and stop in a safe area.

const close = robot.distance() < 18;
const L = robot.lineLeft();
const R = robot.lineRight();

if (close) {
  robot.drive(-0.7, 0.7);
} else if (L) {
  robot.drive(0.1, 0.8);
} else if (R) {
  robot.drive(0.8, 0.1);
} else {
  robot.drive(0.8, 0.8);
}

Robotics at this level is about balancing several goals at once.

Detailed explanation and example

Priorities prevent conflicting actions

A behavior-based robot can have several goals, such as avoid a collision and follow a line. The order of the conditions is a priority system: safety first, then navigation, then ordinary forward motion. Only the first matching branch runs.

Example: make safety the top priority

if (robot.distance() < 18) {
  robot.drive(-0.6, 0.6); // avoid first
} else if (robot.lineLeft()) {
  robot.drive(0.2, 0.8);  // follow the line
} else if (robot.lineRight()) {
  robot.drive(0.8, 0.2);
} else {
  robot.drive(0.6, 0.6);  // fallback
}

A fallback branch is important: it defines what happens when none of the special cases is true.

Try it: Change the order of the obstacle and line checks. Discuss why obstacle avoidance should usually have higher priority.

Advanced · 11

Debugging and tuning

Good robot programs are not written once and finished. They are tested, adjusted, and tuned. Small changes can make a big difference.

  • Increase turning speed if the robot is too slow to avoid obstacles.
  • Reduce forward speed for smooth line following.
  • Use state to remember direction after losing a line.

Debugging means checking what the robot sees and why it makes each decision.

Detailed explanation and example

Change one thing at a time

When a robot behaves badly, first identify what you expected and what actually happened. Check the sensor reading, the condition it should satisfy, and the motor command selected. Then adjust one value and test again so you know what caused the change.

Example tuning log

  • Problem: robot hits obstacles before turning.
  • Change: increase the turn threshold from 15 to 25.
  • Test: run again and observe the closest approach.
  • Next: adjust turning speed if it still cannot turn in time.

Speed, sensor noise, and slippery floor in the simulator can help test whether a behavior still works under less ideal conditions.

Try it: Turn on sensor noise or slippery floor, observe a failure, and change only one setting or code value at a time.

Expert · 12

Feedback and autonomy

Expert robotics is about feedback loops: the robot reads the world, reacts, then reads again. It continuously corrects itself.

const L = robot.lineLeft();
const R = robot.lineRight();

if (L && R) {
  robot.drive(0.8, 0.8);
  state.last = 'straight';
} else if (L) {
  robot.drive(0.2, 0.8);
  state.last = 'left';
} else if (R) {
  robot.drive(0.8, 0.2);
  state.last = 'right';
} else if (state.last === 'left') {
  robot.drive(-0.2, 0.5);
} else {
  robot.drive(0.5, -0.2);
}

At the expert level, the robot does not just follow a fixed rule. It adapts and recovers from uncertainty.

Detailed explanation and example

Feedback and stability

Feedback means repeatedly comparing the current sensor reading with the desired situation and correcting the motor output. A very aggressive correction can make the robot wobble; a very weak correction can make it drift away. Good control balances response speed with smoothness.

Advanced tuning idea

For line following, increase the difference between the two wheel speeds when the robot needs a sharper correction. Reduce that difference for smoother movement. Test several runs rather than judging from one moment, especially when sensor noise is enabled.

Example: add a dead zone

const L = robot.lineLeft();
const R = robot.lineRight();
if (L === R) {
  robot.drive(0.65, 0.65); // both on or both off: go steady
} else if (L) {
  robot.drive(0.25, 0.7);
} else {
  robot.drive(0.7, 0.25);
}

This simplified controller uses moderate steering instead of sharp spins. It is a starting point; different tracks and sensor placement may require different values.

Try it: Compare this smoother controller with the sharper one in Line track mode. Tune the wheel values and explain which is more stable.

Real hardware · beginner build

Build a real obstacle-avoiding robot

Take the simulator ideas into the classroom: assemble a small two-wheel robot, measure distance with an ultrasonic sensor, and use a microcontroller to steer away from obstacles.

Goal: Build a low-voltage, two-wheel robot that moves forward and turns when an object is close. Allow about 2–3 hours for the first build, plus testing time.

🧰 Parts and tools

  • Arduino Uno or compatible board with USB cable
  • 2WD robot chassis, two DC gear motors, two wheels, and a caster
  • TB6612FNG dual motor driver breakout
  • HC-SR04 ultrasonic distance sensor
  • Motor battery pack matched to the motors and driver (for example, 4×AA NiMH when compatible)
  • Jumper wires, small screwdriver, and tape or mounting screws
  • Computer with Arduino IDE; optional multimeter

Before buying: check that the motors’ voltage and current are within the motor driver’s limits. Motor and battery needs differ between kits.

🧠 What each part does

  • Arduino: runs the repeated sense-decide-act program.
  • Ultrasonic sensor: estimates distance ahead.
  • Motor driver: safely switches motor current; the Arduino pins cannot power DC motors directly.
  • Two motors: different left/right speeds steer the chassis.
  • Battery pack: supplies the motors through the driver.

This build uses the same ideas as the simulator's sensors, controller, and motor commands, but real motors have friction, battery limits, and uneven surfaces.

📸 Build it step by step

Start with the robot body, then add its brain and distance sensor. These openly licensed photos show example parts; kits can look different. Use the wiring table below for this project's exact TB6612FNG connections.

1. Make a steady base

Attach the two geared motors to the chassis, fit a wheel on each motor shaft, and secure the small caster at the other end. Check that both wheels spin freely and the frame does not wobble.

2. Mount the robot's brain

Secure the Arduino on top of the chassis with short screws or safe mounting tape. Keep metal parts away from the pins so they cannot accidentally connect. Leave the USB port easy to reach.

3. Give the robot eyes

Mount the HC-SR04 at the front, facing straight ahead. One round part sends a tiny sound pulse; the other listens for its echo. The Arduino uses the echo's travel time to estimate how far away an obstacle is.

What happens next? Connect the motor driver and sensor using the wiring table, then upload the starter program. Keep all power disconnected while wiring, and ask an adult to check the connections before the first test.

🔌 Wiring guide (TB6612FNG + HC-SR04 + Arduino Uno)

Disconnect USB and the motor battery before changing any wires. Use this pin map only with a compatible TB6612FNG breakout; board labels can vary, so check its documentation.

TB6612 GNDArduino GND and battery negativeShared ground/reference

TB6612 PWMA / AIN1 / AIN2Arduino D5 / D7 / D8Left motor speed and direction
TB6612 PWMB / BIN1 / BIN2Arduino D6 / D9 / D10Right motor speed and direction

🛠️ Build and test in stages

  1. Assemble the chassis, mount the motors and wheels, and secure the caster.
  2. Mount the Arduino, motor driver, and ultrasonic sensor facing forward. Keep wheels clear of wires.
  3. With all power disconnected, wire the driver and sensor using the table. Double-check polarity and pin numbers.
  4. Connect USB and upload the program below with the motor battery disconnected. Check for compile/upload errors.
  5. Raise the robot so its wheels are off the table. Connect the motor battery and briefly test; disconnect power if anything heats, smells, or moves unexpectedly.
  6. Place it on a clear floor at low speed. Put a soft obstacle ahead and observe the distance response and turn.
  7. If one wheel turns the wrong way, switch that motor's two output wires with power disconnected, or invert that motor's direction logic in code.

💻 Starter Arduino program

This example measures distance and turns in place below a threshold. The delay gives the ultrasonic sensor time between readings. Test in an open area at low speed; tune the threshold and motor speeds for your chassis.

const int PWMA = 5, AIN1 = 7, AIN2 = 8;
const int PWMB = 6, BIN1 = 9, BIN2 = 10;
const int STBY = 4;
const int TRIG = 11, ECHO = 12;

int readDistanceCm() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(3);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);

  // Stop safely if the sensor does not return an echo.
  unsigned long duration = pulseIn(ECHO, HIGH, 25000UL);
  if (duration == 0) return -1;
  return (int)(duration * 0.0343 / 2.0);
}

void setMotor(int pwmPin, int in1, int in2, int speed) {
  speed = constrain(speed, -180, 180);
  digitalWrite(in1, speed >= 0 ? HIGH : LOW);
  digitalWrite(in2, speed >= 0 ? LOW : HIGH);
  analogWrite(pwmPin, abs(speed));
}

void drive(int left, int right) {
  setMotor(PWMA, AIN1, AIN2, left);
  setMotor(PWMB, BIN1, BIN2, right);
}

void setup() {
  pinMode(PWMA, OUTPUT); pinMode(AIN1, OUTPUT); pinMode(AIN2, OUTPUT);
  pinMode(PWMB, OUTPUT); pinMode(BIN1, OUTPUT); pinMode(BIN2, OUTPUT);
  pinMode(STBY, OUTPUT);
  pinMode(TRIG, OUTPUT); pinMode(ECHO, INPUT);
  digitalWrite(STBY, HIGH);
  Serial.begin(9600);
}

void loop() {
  int distance = readDistanceCm();
  Serial.println(distance); // View readings in Serial Monitor

  if (distance < 0) {
    drive(0, 0); // fail safe if the sensor reading is unavailable
  } else if (distance < 20) {
    drive(-100, 100); // turn in place
    delay(350);
  } else {
    drive(110, 110);  // move forward
  }
  delay(40);
}

Code idea: readDistanceCm() is the sensor input, the if statement is the decision, and drive() controls the motor outputs. The serial monitor helps compare sensor readings with real distances.

🧪 Troubleshooting

  • Arduino resets when motors start: motor power may be pulling down the logic supply; use a suitable separate motor battery and common ground.
  • Distance always reads 200: check TRIG/ECHO wiring, sensor direction, and shared ground.
  • Robot spins instead of going straight: test motors separately; they may be reversed or have different speeds.
  • It hits obstacles before turning: increase the 20 cm threshold or lower forward speed.
  • It turns away continuously: check the sensor is not aimed at the floor or chassis.

🛡️ Classroom safety

  • Use only low-voltage battery-powered kits; never connect student circuits to mains electricity.
  • Have an adult supervise wiring, tools, and battery selection.
  • Disconnect USB and batteries before rewiring. Prevent battery short circuits.
  • Do not use damaged, swollen, hot, or leaking batteries. Charge rechargeable cells only with the correct charger and adult supervision.
  • Keep fingers, hair, and loose wires away from wheels and moving parts.
  • Test on the floor in a clear area at low speed, away from stairs, people, and pets.
